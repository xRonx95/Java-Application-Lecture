Module overview

From source code to a distributable application

A JAR (Java Archive) file combines compiled Java classes and related resources into a single package. An executable JAR also identifies the class that contains the program's main() method, allowing the Java Virtual Machine to start it directly.

02

Core concepts

What each part of the application does

01

JDK

The Java Development Kit provides javac, java, and jar—the three tools used in this lesson.

02

JFrame

A top-level Swing container that provides the title bar, window border, minimize button, and close button.

03

Bytecode

Platform-independent instructions stored in .class files after Java source code is compiled.

04

Manifest

Metadata inside the JAR. Its Main-Class entry tells Java which class must start the program.

A simple explanation for your presentation

“The javac command translates readable Java source code into bytecode. The jar command then packages that bytecode into one archive. Finally, the manifest tells Java where the application begins. When we run java -jar, Java reads the manifest and calls the program's main() method.”

Complete source code

Build the JFrame application

Save this code as src/JFrameLessonApp.java. The class name and filename must match exactly.

JFrameLessonApp.java
import javax.swing.BorderFactory;
import javax.swing.JButton;
import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.JPanel;
import javax.swing.SwingConstants;
import javax.swing.SwingUtilities;
import java.awt.BorderLayout;
import java.awt.Color;
import java.awt.Dimension;
import java.awt.Font;
import java.awt.GridLayout;

public class JFrameLessonApp extends JFrame {

    private final JLabel statusLabel;
    private int clickCount = 0;

    public JFrameLessonApp() {
        setTitle("Executable JAR Demo");
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setMinimumSize(new Dimension(520, 340));

        JPanel header = new JPanel(new GridLayout(2, 1, 0, 5));
        header.setBackground(new Color(31, 41, 55));
        header.setBorder(BorderFactory.createEmptyBorder(28, 30, 24, 30));

        JLabel title = new JLabel("JFrame JAR Application", SwingConstants.CENTER);
        title.setForeground(Color.WHITE);
        title.setFont(new Font("SansSerif", Font.BOLD, 25));

        JLabel subtitle = new JLabel(
                "This window is running from compiled Java code.",
                SwingConstants.CENTER
        );
        subtitle.setForeground(new Color(209, 213, 219));

        header.add(title);
        header.add(subtitle);

        JPanel center = new JPanel(new BorderLayout(0, 20));
        center.setBorder(BorderFactory.createEmptyBorder(38, 55, 38, 55));

        statusLabel = new JLabel("Click the button to test the application.", SwingConstants.CENTER);
        statusLabel.setFont(new Font("SansSerif", Font.PLAIN, 16));

        JButton actionButton = new JButton("Run Action");
        actionButton.setFont(new Font("SansSerif", Font.BOLD, 15));
        actionButton.setFocusPainted(false);
        actionButton.addActionListener(event -> updateStatus());

        center.add(statusLabel, BorderLayout.CENTER);
        center.add(actionButton, BorderLayout.SOUTH);

        add(header, BorderLayout.NORTH);
        add(center, BorderLayout.CENTER);
        pack();
        setLocationRelativeTo(null);
    }

    private void updateStatus() {
        clickCount++;
        statusLabel.setText("Success! Button clicked " + clickCount + " time(s).");
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            JFrameLessonApp app = new JFrameLessonApp();
            app.setVisible(true);
        });
    }
}
1

extends JFrame

Makes the class a window and gives it JFrame behavior.

2

Constructor

Configures the window and creates its Swing components.

3

Event listener

Runs updateStatus() whenever the button is clicked.

4

Event Dispatch Thread

SwingUtilities.invokeLater() safely creates the interface on Swing's UI thread.

Step-by-step procedure

Compile, package, and run the JAR

  1. 1

    Open the project folder

    In the terminal, move to the folder that contains src.

    Windows example
    cd C:\Projects\JFrameJarProject
  2. 2

    Create output folders

    Windows Command Prompt
    if not exist out mkdir out
if not exist dist mkdir dist
  3. 3

    Compile the Java source

    The -d out option places the compiled class in the output folder.

    Terminal
    javac -encoding UTF-8 -d out src\JFrameLessonApp.java

    javac = compiler · -d out = output directory · final value = source file

  4. 4

    Test the compiled class

    Testing before packaging separates source-code problems from JAR problems.

    Terminal
    java -cp out JFrameLessonApp
  5. 5

    Create the manifest file

    Save the following as manifest.txt. Keep a blank line after the last entry.

    manifest.txt
    Main-Class: JFrameLessonApp
  6. 6

    Create the executable JAR

    Terminal
    jar --create --file dist\JFrameLessonApp.jar --manifest manifest.txt -C out .

    --create builds · --file names · --manifest adds metadata · -C out . packages everything inside out

  7. 7

    Run and inspect the JAR

    Terminal
    java -jar dist\JFrameLessonApp.jar
jar --list --file dist\JFrameLessonApp.jar
    Expected result: The JFrame window opens, and the JAR listing includes META-INF/MANIFEST.MF and JFrameLessonApp.class.

Modern JDK shortcut

Build without a separate manifest file

The --main-class option writes the entry point for you.

One JAR command
jar --create --file dist\JFrameLessonApp.jar --main-class JFrameLessonApp -C out .

Build an executable JAR without typing commands

Use this route if your class created the JFrame in Apache NetBeans. The exact output folder depends on whether the project uses Ant, Maven, or Gradle.

⚙️2. Choose main classRight-click the project → Properties → Run → Main Class.
🧹3. Clean and BuildRight-click the project → Clean and Build.
🔎4. Read OutputLook for BUILD SUCCESSFUL and the saved JAR path.

08

Faster workflow

Build everything with one click

Save this as build.bat in the project root. It cleans old files, compiles the program, creates the JAR, and stops immediately if compilation fails.

build.bat
@echo off
setlocal

echo [1/3] Preparing folders...
if exist out rmdir /s /q out
if exist dist rmdir /s /q dist
mkdir out
mkdir dist

echo [2/3] Compiling Java source...
javac -encoding UTF-8 -d out src\JFrameLessonApp.java
if errorlevel 1 (
    echo Build failed during compilation.
    pause
    exit /b 1
)

echo [3/3] Creating executable JAR...
jar --create --file dist\JFrameLessonApp.jar ^
    --main-class JFrameLessonApp -C out .
if errorlevel 1 (
    echo Build failed while creating the JAR.
    pause
    exit /b 1
)

echo Build successful: dist\JFrameLessonApp.jar
echo Starting the application...
java -jar dist\JFrameLessonApp.jar
endlocal
Why this is faster: After editing the Java code, double-click build.bat instead of typing each command again.

Additional lesson topics

Packages, pictures, libraries, and installers

🗂️

Topic A: Java packages

If the source begins with package com.school.app;, the main class becomes com.school.app.JFrameLessonApp. The folder structure and manifest must match that full name.

🖼️

Topic B: Images and resources

Place icons under a resource folder and load them from the classpath. This keeps the picture inside the JAR and avoids computer-specific paths.

📚

Topic C: Third-party libraries

A normal JAR may not contain external libraries. Maven Shade or Gradle Shadow can create a “fat JAR” that includes required dependencies.

💿

Topic D: Native installers

jpackage can create a Windows installer or application image and include a Java runtime for computers that do not have Java installed.

Load an image safely from inside the JAR

Example project path: src/images/school-logo.png. Use a leading slash so Java searches from the classpath root.

Java resource example
var imageUrl = JFrameLessonApp.class.getResource("/images/school-logo.png");
if (imageUrl == null) {
    throw new IllegalStateException("Logo resource was not found");
}
setIconImage(new javax.swing.ImageIcon(imageUrl).getImage());

Create an application image with jpackage

Windows example
jpackage --type app-image ^
  --name JFrameLessonApp ^
  --input dist ^
  --main-jar JFrameLessonApp.jar ^
  --main-class JFrameLessonApp ^
  --dest installer
New idea: An executable JAR is portable across systems with Java. A native package is easier for end users but must usually be built separately for Windows, macOS, and Linux.

Problem solving

Common errors and their solutions

“Unable to access jarfile”+

The path or filename is incorrect. Run dir dist to confirm the JAR exists, then use its exact name.

“No main manifest attribute”+

The manifest does not contain a valid Main-Class entry. Rebuild with --main-class JFrameLessonApp or correct manifest.txt.

“Could not find or load main class”+

The class name, package name, manifest value, or folder structure does not match. Java names are case-sensitive.

The JAR opens and immediately closes+

Run it from a terminal with java -jar ... so the error remains visible. Confirm that the computer has a compatible Java runtime.

Double-click does not open the JAR+

The .jar file association may be missing. Test with java -jar. For end users without Java, package a native installer with jpackage.

Images or other resources are missing+

Put resources on the classpath and load them with getResource(). Avoid absolute paths such as C:\Users\... because they only work on one computer.

Professional practice

Make the application reliable and distributable

Use packages

For larger projects, place classes in a package such as com.school.app and set the main class to com.school.app.JFrameLessonApp.

Use layout managers

Prefer BorderLayout, GridLayout, or GridBagLayout so the interface resizes correctly.

Keep work off the UI thread

Use SwingWorker for slow database, file, or network tasks so the JFrame does not freeze.

Test on a clean computer

Check the minimum Java version and confirm that every image, configuration file, and dependency is included.

Use a build tool later

Maven or Gradle is better for projects with libraries, tests, many source files, and repeatable releases.

Consider jpackage

A JAR still needs Java. jpackage can create a platform-specific installer that includes a runtime.

Knowledge check

1. What is the purpose of javac? Show answer

It compiles Java source files into JVM bytecode stored in .class files.

2. Why does an executable JAR need a main class? Show answer

Java needs to know which class contains the main() method that starts the application.

3. Why should a Swing interface start with invokeLater()? Show answer

It schedules interface creation on Swing's Event Dispatch Thread, which keeps UI operations thread-safe.

4. What does -C out . mean in the JAR command? Show answer

It changes into the out folder and packages all content from that folder into the JAR.

5. Does an executable JAR automatically include Java itself? Show answer

No. The target computer normally needs a compatible Java runtime unless the app is distributed using a tool such as jpackage.
