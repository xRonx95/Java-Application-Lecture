Topic 01

Run vs. Debug

Learning objective

Differentiate normal program execution from debugging execution.

What does “Run” mean?

Running executes a program normally from beginning to end. The computer follows the instructions, displays output, and stops when the program finishes or encounters an unhandled error.

What does “Debug” mean?

Debugging executes the same program with tools that let you pause it, inspect values, follow its control flow, and locate the reason for incorrect behavior. A program may run without crashing and still contain a logic error.

▶

Run

  • Executes at normal speed
  • Shows the final behavior
  • Stops at errors or completion
◆

Debug

  • Can pause at breakpoints
  • Shows variables and call flow
  • Helps explain why a bug occurs
Explanation tip: Compare debugging to pausing a recorded game so you can study exactly what every player is doing.

Topic 03

The Debugging Process

Learning objective

Apply a repeatable debugging method instead of guessing.

Debugging is an evidence-based investigation. Use the following cycle whenever a program behaves incorrectly.

01

Reproduce

Find exact actions or input that consistently cause the problem.

02

Observe

Read the output, error message, and complete stack trace.

03

Hypothesize

State one specific possible cause based on the evidence.

04

Test

Use breakpoints, watches, or temporary output to test the idea.

05

Fix

Make one focused correction without changing unrelated code.

06

Verify

Run normal, boundary, and invalid-input tests after the change.

Remember: Observe → Hypothesize → Test → Fix → Verify.
Topic 04

Breakpoints

Learning objective

Place useful breakpoints and explain what happens when one is reached.

A breakpoint is a marker that pauses the program before a selected line executes. While paused, you can inspect local variables, object fields, method parameters, threads, and the call stack.

Breakpoint example
int total = 0;
for (int i = 0; i < scores.length; i++) {
    total += scores[i]; // Place breakpoint here
}
double average = (double) total / scores.length;

Line breakpoint

Pauses every time execution reaches the selected line.

Conditional breakpoint

Pauses only when an expression such as i == 2 is true.

Good placement

Choose a line near the first point where the program state becomes suspicious.

Important: A breakpoint does not fix or permanently stop a program. It temporarily freezes the current execution for inspection.
Topic 05

Debugger Step Controls

Learning objective

Choose correctly among Resume, Step Over, Step Into, Step Out, Restart, and Stop.

ControlWhat it doesWhen to use it
ResumeContinues normal execution.Move to the next breakpoint or program end.
Step OverExecutes the current line without entering called methods.The called method is not being investigated.
Step IntoEnters the method called on the current line.You suspect the problem is inside that method.
Step OutFinishes the current method and returns to its caller.You have inspected enough of the current method.
RestartStops and starts the debugging session again.You need to reproduce the program from the beginning.
StopTerminates the current debugging session.The current run is no longer useful.
Choosing a step command
double finalPrice = calculateDiscount(price);
printReceipt(finalPrice);

// Step Into to inspect calculateDiscount().
// Step Over to execute it as one line.
// Step Out to finish it and return to the caller.
Topic 06

Inspect Program State

Learning objective

Use Variables, Watches, and the Call Stack to explain program behavior.

V

Variables

Shows the values currently available in the method or block where execution is paused.

W

Watches

Evaluates expressions you want to monitor, such as total / (double) count.

C

Call Stack

Shows the chain of method calls that led to the current line.

E

Evaluate Expression

Tests an expression while the program is paused without adding it permanently to the code.

Ask three questions: What values do I have? How did execution get here? What line will execute next?
Topic 07

Types of Programming Errors

Learning objective

Classify syntax, runtime, and logic errors using evidence.

Compile time

Syntax Error

Violates Java language rules and prevents successful compilation.

int age = 18 // Missing ;
During execution

Runtime Error

Occurs while the program is executing and often creates an exception.

int answer = 10 / 0;
Wrong result

Logic Error

The program finishes but produces an incorrect result.

int area = length + width;
Topic 08

Stack Traces and Exceptions

Learning objective

Read an exception message and locate the relevant source line.

A stack trace names the exception, gives a message, and lists method calls. Read the exception type first, then locate the first line that belongs to your own code.

Example stack trace
Exception in thread "main"
java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
    at GradeApp.calculate(GradeApp.java:18)
    at GradeApp.main(GradeApp.java:7)
  1. Exception type: ArrayIndexOutOfBoundsException
  2. Message: Index 3 is invalid for an array containing three items.
  3. First source location: Start investigating GradeApp.java, line 18.
  4. Caller: The failing method was called from line 7 of main.
Remember: The listed line is where the failure appeared. The incorrect value may have been created earlier.

Prevent Bugs with Input Validation

Learning objective

Check user input before using it in a calculation.

SafeAge.java
Scanner input = new Scanner(System.in);
System.out.print("Enter age: ");

if (input.hasNextInt()) {
    int age = input.nextInt();
    if (age >= 0 && age <= 120) {
        System.out.println("Accepted: " + age);
    } else {
        System.out.println("Age must be from 0 to 120.");
    }
} else {
    System.out.println("Please enter a whole number.");
}

Normal input

Test 18. It should be accepted.

Boundary input

Test 0 and 120.

Invalid input

Test -1, 121, and hello.

Topic 13 — New Lesson

Debug Loops and Arrays

Learning objective

Trace an array loop and prevent off-by-one errors.

Safe array loop
int[] grades = {88, 92, 79};
int total = 0;

for (int i = 0; i < grades.length; i++) {
    total += grades[i];
}
  1. 1
    Place a breakpoint inside the loop

    Pause before total changes.

  2. 2
    Watch the index

    Confirm that i changes from 0 to 1 to 2.

  3. 3
    Watch the total

    It should change from 0 to 88 to 180 to 259.

  4. 4
    Confirm the exit

    When i becomes 3, the condition is false and the loop stops safely.

Common mistake: i <= grades.length executes once too many and tries to read invalid index 3.
Topic 14 — New Lesson

Trace Methods and the Call Stack

Learning objective

Follow values into a method, through its return statement, and back to the caller.

Method example
static double calculateAverage(int total, int count) {
    return (double) total / count;
}

public static void main(String[] args) {
    double result = calculateAverage(259, 3);
    System.out.println(result);
}

Guided trace

  1. Put a breakpoint on the line that calls calculateAverage.
  2. Use Step Into and inspect total and count.
  3. Step to the return statement and predict the result.
  4. Use Step Out and confirm that result receives the returned value.
Activity 15

Find and Fix the Bugs

Your task

Predict the result, identify three problems, and choose a useful breakpoint before revealing the solution.

GradeChecker.java
public class GradeChecker {
    public static void main(String[] args) {
        int[] grades = {88, 92, 79};
        int total = 0;

        for (int i = 0; i <= grades.length; i++) {
            total =+ grades[i];
        }

        double average = total / grades.length;
        System.out.println("Average: " + average);
    }
}

Suggested solution

  1. Runtime error: Change i <= grades.length to i < grades.length.
  2. Logic error: Change total =+ grades[i] to total += grades[i].
  3. Accuracy issue: Use double average = (double) total / grades.length;.
  4. Breakpoint: Pause at the first line inside the loop, then watch i, grades[i], and total.
