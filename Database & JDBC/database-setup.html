Introduction

Lesson Overview

A database is an organized collection of information that an application can store, search, update, and protect. In a PHP website, the database commonly stores user accounts, appointments, records, messages, and other structured information.

This module demonstrates a local development setup using XAMPP as the server package, MySQL or MariaDB as the database management system, phpMyAdmin as the browser-based management interface, and PHP as the application language.

i

Important distinction

XAMPP is the local server package. MySQL/MariaDB manages the data. phpMyAdmin is only a visual administration tool. PHP is the application that communicates with the database.

Expected Outcomes

Learning Objectives

At the end of this lesson, the learner should be able to:

  • 01 explain the roles of a database, table, record, field, primary key, and foreign key;
  • 02 start and verify the Apache and MySQL services in XAMPP;
  • 03 create a database using an appropriate name and character set;
  • 04 create a structured table through SQL or phpMyAdmin;
  • 05 connect a PHP application to MySQL using a reusable configuration file;
  • 06 test the connection and resolve common setup errors; and
  • 07 apply basic security and data-protection practices.

Foundation

Core Database Concepts

DB

Database

A named container that groups related tables for one system or project.

▦

Table

A structured collection of related information arranged in rows and columns.

↔

Record and Field

A record is one row. A field is one property or column within that row.

KEY

Primary Key

A unique value, commonly an auto-incrementing ID, that identifies each record.

FK

Foreign Key

A field that connects a record to the primary key of another table.

SQL

SQL

Structured Query Language is used to create, read, update, and delete data.

Guided Demonstration

Step-by-Step Database Setup

Complete the following steps in order. After each major step, verify the expected result before moving forward.

▶

Interactive Run Example

Select Run Example beside a code sample to display its expected result in a GUI-style preview. These previews run entirely in the browser for teaching purposes; they do not execute PHP, MySQL, or modify a real database.

1

Server Preparation

Start Apache and MySQL in XAMPP

  1. Open the XAMPP Control Panel using administrator permission when required.
  2. Select Start beside Apache.
  3. Select Start beside MySQL.
  4. Confirm that both module rows turn green and display active process and port information.
Checkpoint: Open http://localhost/. The XAMPP dashboard should appear without an error.
2

Database Administration

Open phpMyAdmin

  1. Open a browser.
  2. Enter http://localhost/phpmyadmin/ in the address bar.
  3. Confirm that the phpMyAdmin home screen displays the server and database navigation panel.
3

Schema Creation

Create the Database

  1. Select New in the left navigation panel.
  2. Enter database_lesson as the database name.
  3. Select utf8mb4_unicode_ci as the collation.
  4. Select Create.
✓

Naming standard

Use descriptive lowercase names with underscores, such as student_portal or parish_records. Avoid spaces, punctuation, and vague names such as db1.

4

Table Design

Create a Students Table with SQL

  1. Select the newly created database_lesson database.
  2. Open the SQL tab.
  3. Enter the SQL statement below, then select Go.
SQL · Create table 
CREATE TABLE students (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    student_number VARCHAR(30) NOT NULL UNIQUE,
    full_name VARCHAR(150) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    course VARCHAR(100) NOT NULL,
    year_level TINYINT UNSIGNED NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

Why these data types were selected

FieldData typeReason
idINT UNSIGNEDStores a positive numeric identifier.
student_numberVARCHAR(30)May contain letters, numbers, or hyphens.
full_nameVARCHAR(150)Stores variable-length text efficiently.
year_levelTINYINT UNSIGNEDUses a small positive whole number.
created_atTIMESTAMPRecords when the row was created.

6

Application Connection

Create the Reusable PHP Connection File

Create config/db.php inside the project folder. Keeping the connection in one file prevents repeated configuration and simplifies maintenance.

PHP · config/db.php 
<?php
declare(strict_types=1);

$dbHost = 'localhost';
$dbName = 'database_lesson';
$dbUser = 'root';
$dbPass = ''; // Default local XAMPP password is blank.

mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

try {
    $conn = new mysqli($dbHost, $dbUser, $dbPass, $dbName);
    $conn->set_charset('utf8mb4');
} catch (mysqli_sql_exception $exception) {
    error_log('Database connection error: ' . $exception->getMessage());
    http_response_code(500);
    exit('Unable to connect to the database.');
}
!

Local and hosted credentials are different

The default local XAMPP account may use root with a blank password. A hosted website must use the exact database host, database name, username, and password supplied by the hosting provider.

Connection Verification

Test the Database from PHP

Create test-connection.php in the project root.

PHP · test-connection.php 
<?php
require_once __DIR__ . '/config/db.php';

$result = $conn->query('SELECT COUNT(*) AS total FROM students');
$row = $result->fetch_assoc();
?>
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Database Test</title>
</head>
<body>
  <h1>Database connection successful</h1>
  <p>Student records: <?= (int) $row['total'] ?></p>
</body>
</html>

Open http://localhost/database_lesson/test-connection.php. A success message and a record count of 2 should appear.

Professional Practice

Database Security and Data Protection

01

Protect credentials

Do not publish real database passwords in screenshots, repositories, or public files.

02

Use prepared statements

Parameterize user input to reduce SQL injection risk.

03

Hash passwords

Use PHP password_hash() and password_verify(); never save plain-text passwords.

04

Limit privileges

Give a database account only the permissions required by the application.

05

Validate input

Check data type, length, format, and allowed values on the server.

06

Maintain backups

Create regular backups and test that important backups can be restored.

Prepared statement example

PHP · Safe insert 
$statement = $conn->prepare(
    'INSERT INTO students
     (student_number, full_name, email, course, year_level)
     VALUES (?, ?, ?, ?, ?)'
);

$statement->bind_param(
    'ssssi',
    $studentNumber,
    $fullName,
    $email,
    $course,
    $yearLevel
);

$statement->execute();

Problem Solving

Common Errors and Recommended Solutions

Observed problemLikely causeRecommended action
MySQL stops immediatelyPort conflict, improper shutdown, or damaged data filesReview the XAMPP log first. Confirm that another MySQL service is not using port 3306.
Access denied for userIncorrect username, password, or account privilegeVerify all credentials and confirm that the account can access the selected database.
Unknown databaseThe database name is incorrect or was not createdCompare $dbName with the exact name shown in phpMyAdmin.
Table doesn't existWrong database selected or SQL import incompleteOpen the database and verify that the expected table appears in the navigation panel.
Blank PHP pageA PHP error occurred while error display is disabledReview the PHP/Apache error log and correct the first reported error.
Imported text displays incorrectlyCharacter-set mismatchUse utf8mb4 consistently for the database, tables, connection, and source file.
Connection works locally but not onlineHosting credentials differ from XAMPP credentialsUse the database details issued by the hosting provider; do not upload local credentials unchanged.

A professional troubleshooting sequence

  1. ReadRecord the exact error message.
  2. LocateIdentify whether it comes from Apache, MySQL, PHP, or SQL.
  3. VerifyCheck service status, credentials, names, paths, and ports.
  4. ChangeApply one controlled correction at a time.
  5. RetestRepeat the same test and document the result.

Knowledge Check

Assessment

Answer each question before viewing the suggested answer.

1 What is the purpose of a primary key?

A primary key uniquely identifies each record in a table and prevents duplicate identities.

2 Why is utf8mb4 recommended?

It supports a broad range of Unicode characters and helps preserve multilingual text consistently.

3 Why should the database connection be stored in config/db.php?

It centralizes configuration, avoids repeated code, and makes maintenance more consistent.

4 What should be checked when an “Access denied” error appears?

Verify the database username, password, host, and the privileges assigned to that user.

5 How do prepared statements improve security?

They separate SQL instructions from user-supplied data, reducing the risk of SQL injection.

Reference

Glossary of Terms

Collation
The rules used to compare and sort text in a database.
CRUD
Create, Read, Update, and Delete—the four basic data operations.
DBMS
Database Management System; software used to organize and control databases.
Localhost
The current computer acting as its own local server, commonly addressed as 127.0.0.1.
MariaDB
A relational database management system compatible with common MySQL workflows.
Schema
The formal structure of a database, including its tables, columns, keys, and relationships.
SQL injection
An attack in which unsafe input changes the intended meaning of an SQL query.
XAMPP
A local development package that includes Apache, MariaDB, PHP, and related tools.

Lesson Completion

Key Takeaways

A reliable database setup depends on four connected layers: running server services, a well-designed schema, correct connection settings, and secure application code. Verify each layer separately and record exact errors when troubleshooting.
