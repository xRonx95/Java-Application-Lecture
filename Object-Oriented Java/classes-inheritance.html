THE FOUNDATION

Classes and objects

A class is a blueprint that describes data and behavior. An object is a real instance created from that blueprint.

CLASS · BLUEPRINT
▱

Smartphone design

Defines the properties and actions every phone will have.

→
OBJECTS · INSTANCES

Actual smartphones

Each object has its own color, storage, and battery level.

Picture it: one blueprint, many objects

Simple definition

Think of a cookie cutter as the class and each cookie as an object. One blueprint can produce many independent objects.

Explain it this way

“The class says what an object has and what it can do. The object holds the actual values.”

CarDemo.java
class Car {
  String color;

  void drive() {
    System.out.println("Moving!");
  }
}

Car myCar = new Car();
myCar.color = "Blue";
myCar.drive();

03
STARTING AN OBJECT

Constructors, parameters, and this

A constructor runs once when an object is created. It gives the object a valid starting state.

Book.java
class Book {
  private String title;
  private int pages;

  Book(String title, int pages) {
    this.title = title;
    this.pages = pages;
  }
}

Book novel = new Book("Noli Me Tangere", 480);

Trace the values

  1. 1

    new Book(...)

    Java reserves memory for one Book object.

  2. 2

    Arguments enter

    "Noli Me Tangere" and 480 become parameter values.

  3. 3

    this points to the object

    The values are copied into that object’s fields.

DEFAULT CONSTRUCTOR

No parameters

If you write no constructor, Java supplies a no-argument constructor. Once you write any constructor, that automatic one disappears.

OVERLOADING

More than one constructor

A class can offer different parameter lists, such as Book() and Book(String title).

CONSTRUCTOR CHAINING

Reuse setup with this(...)

One constructor can call another constructor in the same class as its first statement.

Quick checkWhy does this.title = title; use this? The left side is the object’s field; the right side is the constructor parameter.
04
PROTECTING DATA

Encapsulation & access modifiers

Encapsulation keeps an object’s data safe by controlling how other code can read or change it.

ModifierSame classSame packageChild classEverywhere
privateMost restrictedYes———
defaultNo keywordYesYesPackage only—
protectedInheritance-friendlyYesYesYes—
publicLeast restrictedYesYesYesYes
BankAccount.java
class BankAccount {
  private double balance;

  public void deposit(double amount) {
    if (amount > 0) balance += amount;
  }

  public double getBalance() {
    return balance;
  }
}

Why not make every field public?

If balance were public, any code could set an invalid value. A controlled method can check rules first.

Key idea

Encapsulation is not simply “using getters and setters.” It means protecting valid object state.

05
SHARED OR INDIVIDUAL?

Static members vs. instance members

Instance members belong to each object. A static member belongs to the class and is shared by all objects.

StudentCounter.java
class Student {
  static int studentCount = 0; // shared
  String name;                       // per object

  Student(String name) {
    this.name = name;
    studentCount++;
  }
}

Student a = new Student("Ana");
Student b = new Student("Ben");
System.out.println(Student.studentCount); // 2
06
REUSING BEHAVIOR

What is inheritance?

Inheritance lets a new class reuse and specialize accessible members of an existing class. Java uses extends.

PARENT / SUPERCLASS

Animal

name · eat() · sleep()

extends →
CHILD / SUBCLASS

Dog

breed · bark() · inherited members

Animal.java
class Animal {
  String name;
  void eat() {
    System.out.println(name + " eats.");
  }
}
Dog.java
class Dog extends Animal {
  void bark() {
    System.out.println("Woof!");
  }
}
Dog pet = new Dog();
pet.name = "Milo";
pet.eat();  // inherited
pet.bark(); // own method
Explain it this way

“A Dog can use Dog features and accessible Animal features. The child gains members, but the parent does not gain the child’s special members.”

CLASS HIERARCHIES

Types of inheritance

Java classes support single, multilevel, and hierarchical inheritance. Multiple inheritance of classes is not allowed.

AB
SUPPORTED

Single

One child extends one direct parent.

Dog extends Animal
ABC
SUPPORTED

Multilevel

A child becomes a parent for another class.

Puppy extends Dog
A
BC
SUPPORTED

Hierarchical

Several children share one parent.

Dog / Cat extend Animal
AB
C
INTERFACES ONLY

Multiple

A class cannot extend two classes, but it can implement interfaces.

C implements A, B
Why can’t class C extend both A and B?

If A and B contain the same method, Java would not know which implementation to inherit. This is called the diamond problem.

08
ADDING CAPABILITIES

Interfaces and multiple capabilities

An interface describes a capability a class promises to provide. A class may extend one class and implement several interfaces.

Duck.java
interface Swimmable { void swim(); }
interface Flyable   { void fly(); }

class Animal { void eat() { } }

class Duck extends Animal
           implements Swimmable, Flyable {
  public void swim() { System.out.println("Paddle"); }
  public void fly()  { System.out.println("Flap"); }
}
Try itCreate a Robot class that implements Swimmable. Its method can print "Water mode activated".
09
CONNECTING TO THE PARENT

The super keyword

super refers to the immediate parent part of the current object. It has three common uses.

01

Call a parent constructor

super(name);

Must be the first statement in a child constructor.

02

Call a parent method

super.display();

Useful when the child also overrides that method.

03

Access a parent field

super.name

Distinguishes a hidden parent field from a child field.

Employee.java
class Person {
  String name;
  Person(String name) { this.name = name; }
  void introduce() { System.out.println("I am " + name); }
}

class Employee extends Person {
  String role;
  Employee(String name, String role) {
    super(name); // parent constructor
    this.role = role;
  }
  void introduce() {
    super.introduce(); // parent method
    System.out.println("My role is " + role);
  }
}
10
SPECIALIZING BEHAVIOR

Method overriding & polymorphism

Overriding happens when a child provides its own version of an inherited method using the same signature.

INHERITANCE

Overriding

A child replaces inherited behavior.

  • Different classes
  • Same name
  • Same parameters
  • Runtime decision
CONVENIENCE

Overloading

Methods share a name but accept different inputs.

  • Usually same class
  • Same name
  • Different parameters
  • Compile-time decision
PolymorphismDemo.java
class Animal {
  void sound() { System.out.println("Animal sound"); }
}
class Dog extends Animal {
  @Override
  void sound() { System.out.println("Woof"); }
}
Animal pet = new Dog();
pet.sound(); // Woof — actual object decides
ASK THE CLASS

“The variable type is Animal, so why does Java run the Dog method?”

Dynamic method dispatch chooses the method using the actual object at runtime.
11
USING PARENT REFERENCES SAFELY

Polymorphism, casting, and instanceof

A parent reference can point to a child object. It can call overridden methods, but child-only methods require a safe cast.

What the reference can see

SafeCasting.java
Animal pet = new Dog();
pet.sound(); // allowed; prints Woof

// pet.bark(); // compile error

if (pet instanceof Dog dog) {
  dog.bark(); // safe child access
}
UPCASTING

Animal pet = new Dog();

Automatic and safe. It lets different child objects share a parent reference type.

DOWNCASTING

Dog dog = (Dog) pet;

Explicit and potentially unsafe. Check the actual type with instanceof first.

Avoid ClassCastException

Never cast just because the compiler allows the syntax. Confirm the object really has that child type.

12
CHOOSING A DESIGN

IS-A vs HAS-A

Not every relationship should use inheritance. Use this sentence test before writing extends.

IS-AInheritance

A Dog is an Animal.

The child is a more specific version of the parent.

class Dog extends Animal
  • Use for true specialization
  • Creates tighter coupling
HAS-AComposition

A Car has an Engine.

One object contains or uses another object.

class Car { Engine engine; }
  • Use for parts and capabilities
  • Usually more flexible
Design rule

Prefer composition when the relationship is “has-a,” when behavior may change independently, or when the inheritance sentence sounds unnatural.

CONTROLLING THE HIERARCHY

Abstract and final classes

Java provides tools for requiring child behavior or stopping inheritance where it should end.

A

abstract

Cannot be instantiated directly. Children must implement its abstract methods.

abstract class Shape
F

final class

Cannot be extended. Use it when the class design must remain unchanged.

final class Token
M

final method

Is inherited but cannot be overridden by a child.

final void validate()
Shape.java
abstract class Shape {
  abstract double area();
  void describe() { System.out.println("I am a shape."); }
}
class Circle extends Shape {
  double radius;
  @Override
  double area() { return Math.PI * radius * radius; }
}

CHECK YOUR UNDERSTANDING

Knowledge check

Choose an answer before opening the explanation.

01What is the difference between a class and an object?View answer

A class is a blueprint or type definition. An object is a specific instance with its own values in memory.

02Which keyword creates inheritance between Java classes?View answer

extends, as in class Dog extends Animal.

03Can a child directly access a parent’s private field?View answer

No. The parent can expose controlled access through a suitable method.

04Why do we use @Override?View answer

It declares our intent and lets the compiler catch signature mistakes.

05Should Car extend Engine? Why?View answer

No. A car has an engine; it is not a type of engine. Use composition.

06What is the difference between this(...) and super(...)?View answer

this(...) calls another constructor in the same class. super(...) calls a constructor in the immediate parent class. Either call must be the constructor’s first statement.

07When should a field be static?View answer

Use static when one value belongs to the class as a whole and should be shared by every object, such as a counter or fixed school name.

08How can one class have several capabilities if it cannot extend two classes?View answer

It can implement multiple interfaces, such as class Duck extends Animal implements Swimmable, Flyable.

09What does Animal pet = new Dog(); demonstrate?View answer

It demonstrates upcasting and polymorphism: a parent reference points to a child object, and overridden methods use the child implementation.

10Why should you check instanceof before downcasting?View answer

It confirms the object has the requested child type and helps prevent a runtime ClassCastException.
