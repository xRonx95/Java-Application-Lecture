01 · Overview

What will you learn?

Polymorphism is one of the four main principles of object-oriented programming, together with encapsulation, inheritance, and abstraction. It lets a program use a common type while allowing each object to perform its own version of an action.

02 · Core idea

What does polymorphism mean?

The word polymorphism comes from words meaning “many forms.” In programming, it means that one type, method name, or interface can work in more than one form.

CLASSROOM DEFINITION

Polymorphism is the ability to treat different objects as one common type while each object responds according to its actual class.

01

One common type

A parent class or interface gives different objects a shared identity.

Animal pet
02

Many object forms

The reference may point to a Dog, Cat, Cow, or another valid subtype.

new Dog()
03

Different behavior

The same method call can run a different implementation for each object.

pet.makeSound()
Common type+Different objects+Same message=Different behavior

05 · Specialized behavior

Method overriding

Overriding happens when a child class provides its own implementation of a method already declared in its parent class. The method name and parameter list must match.

Animal hierarchyJAVA
class Animal {
    public void makeSound() {
        System.out.println("An animal makes a sound.");
    }
}

class Dog extends Animal {
    @Override
    public void makeSound() {
        System.out.println("Woof!");
    }
}

class Cat extends Animal {
    @Override
    public void makeSound() {
        System.out.println("Meow!");
    }
}
Class definitions
No console output.
Result: Animal, Dog, and Cat classes are defined, with Dog and Cat overriding makeSound().

Tip: run the Java code in NetBeans or the terminal to verify the same result.

1

Same signature

Use the same method name and parameter types.

2

Inheritance required

The method must come from a parent class or interface.

3

Compatible return

The return type must be the same or a valid covariant type.

4

No weaker access

An overridden method cannot become more restrictive.

Use @Override. It tells the compiler to check that you are truly overriding a method. It catches spelling mistakes and incorrect parameters.

06 · Runtime polymorphism

Dynamic method dispatch

When an overridden method is called through a parent reference, Java looks at the actual object at runtime. It then executes that object's version of the method.

PolymorphismDemo.javaJAVA
public class PolymorphismDemo {
    public static void main(String[] args) {
        Animal pet = new Dog();
        pet.makeSound();        // Woof!

        pet = new Cat();
        pet.makeSound();        // Meow!
    }
}
Runtime dispatch
Woof!
Meow!

Tip: run the Java code in NetBeans or the terminal to verify the same result.

1

Compile time: Java checks whether Animal has an accessible makeSound() method.

2

Runtime: Java checks the actual object currently stored in pet.

3

Method choice: A Dog runs Dog.makeSound(); a Cat runs Cat.makeSound().

KEY IDEA

The reference type controls what members can be called. The actual object type controls which overridden method body runs.

08 · Compile-time polymorphism

Method overloading

Overloading uses the same method name with different parameter lists in the same class. The compiler selects the correct method by looking at the arguments in the call.

Calculator.javaJAVA
class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
Overloaded calls
add(2, 5) = 7
add(2.5, 5.0) = 7.5
add(2, 5, 8) = 15

Tip: run the Java code in NetBeans or the terminal to verify the same result.

add(2, 5)uses two int parameters
add(2.5, 5.0)uses two double parameters
add(2, 5, 8)uses three int parameters
Changing only the return type is not enough.

int add(int, int) and double add(int, int) have the same parameter list, so Java treats them as duplicate methods.

10 · Abstraction

Polymorphism with abstract classes

An abstract class can define shared data and behavior while requiring child classes to complete certain methods. You cannot instantiate an abstract class directly, but you can use it as a reference type.

Shape.javaJAVA
abstract class Shape {
    abstract double area();

    void describe() {
        System.out.println("I am a shape.");
    }
}

class Circle extends Shape {
    private double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}
Abstract class result
No console output from the definition alone.
Example result: a Circle object can provide its own area() calculation.

Tip: run the Java code in NetBeans or the terminal to verify the same result.

Why this helps: Every Shape promises an area() method, but each child class decides how its own area is calculated.

11 · Common contract

Polymorphism with interfaces

An interface describes a capability or contract. Unrelated classes can implement the same interface and then be processed through one interface reference.

PaymentMethod.javaJAVA
interface PaymentMethod {
    void pay(double amount);
}

class CashPayment implements PaymentMethod {
    @Override
    public void pay(double amount) {
        System.out.println("Paid ₱" + amount + " in cash.");
    }
}

class CardPayment implements PaymentMethod {
    @Override
    public void pay(double amount) {
        System.out.println("Charged ₱" + amount + " to a card.");
    }
}
Interface result

Result: CashPayment and CardPayment each provide their own pay(amount) behavior.

Upcasting

EXPLICIT

Downcasting

14 · Important limits

What is not dynamically polymorphic?

Runtime polymorphism applies to overridden instance methods. Fields, static methods, private methods, final methods, and constructors do not use dynamic method dispatch.

Fields

A field is selected using the reference type, not the actual object type. Prefer getter methods when behavior must vary.

pet.name

Static methods

A child may hide a static method, but it does not override it. The reference or class name controls the call.

Animal.info()

Private methods

A child cannot override a private parent method because that method is not inherited.

private void helper()

Final methods

A method marked final is inherited but cannot be replaced by a child class.

final void identify()

Constructors

Constructors initialize objects and are not inherited, so they cannot be overridden.

Dog()

Overloaded methods

Overloads are selected at compile time using the declared argument types, not runtime dispatch.

print(Animal a)
Fields and methods behave differentlyJAVA
class Animal {
    String label = "Animal";
    void show() { System.out.println("Animal method"); }
}

class Dog extends Animal {
    String label = "Dog";
    @Override
    void show() { System.out.println("Dog method"); }
}

Animal pet = new Dog();
System.out.println(pet.label);  // Animal (field)
pet.show();                     // Dog method (overridden method)

Rule of thumb:

If you need subtype-specific behavior, put that behavior in an overridable instance method instead of reading a field directly.

15 · Good software design

Why programmers use polymorphism

↻

Reusable code

One method can work with many related object types.

+

Easy extension

Add a new subtype without rewriting every caller.

≋

Less repetition

A shared loop replaces separate code for every class.

◇

Loose coupling

Code depends on a stable abstraction, not one exact class.

WITHOUT POLYMORPHISM payCash() payCard() payGCash()

Every new payment type may require another branch or method.

WITH POLYMORPHISM processPayment(PaymentMethod method)

Any class that follows the contract can be accepted.

🎯
Design principle to remember

Program to a parent type or interface when callers only need the shared behavior. Use a specific child type only when child-specific behavior is truly required.

16 · Guided example

Complete example: employee payroll

The payroll program stores different employees in one Employee array. Each employee calculates pay differently, but the loop calls the same calculatePay() method.

PayrollDemo.javaJAVA
abstract class Employee {
    private String name;

    Employee(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }

    public abstract double calculatePay();
}

class FullTimeEmployee extends Employee {
    private double monthlySalary;

    FullTimeEmployee(String name, double salary) {
        super(name);
        monthlySalary = salary;
    }

    @Override
    public double calculatePay() {
        return monthlySalary;
    }
}

class PartTimeEmployee extends Employee {
    private double hourlyRate;
    private int hoursWorked;

    PartTimeEmployee(String name, double rate, int hours) {
        super(name);
        hourlyRate = rate;
        hoursWorked = hours;
    }

    @Override
    public double calculatePay() {
        return hourlyRate * hoursWorked;
    }
}

public class PayrollDemo {
    public static void main(String[] args) {
        Employee[] employees = {
            new FullTimeEmployee("Ana", 30000),
            new PartTimeEmployee("Ben", 150, 80)
        };

        for (Employee employee : employees) {
            System.out.printf("%s: ₱%.2f%n",
                    employee.getName(), employee.calculatePay());
        }
    }
}
Payroll output
Ana: ₱30000.00
Ben: ₱12000.00

Tip: run the Java code in NetBeans or the terminal to verify the same result.

PROGRAM OUTPUT Ana: ₱30000.00
Ben: ₱12000.00
  1. The abstract parent defines the contract. Every Employee must provide calculatePay().
  2. Each child overrides the method. Full-time and part-time pay use different formulas.
  3. The array uses the parent type. It can store either employee subtype.
  4. The loop is reusable. The same code processes every employee.
  5. Java dispatches dynamically. The actual object chooses the correct pay calculation.

Short teacher explanation

“Notice that the loop never asks whether an employee is full-time or part-time. It simply tells every Employee object to calculate its pay. Each object already knows how to perform that job. That is the power of polymorphism.”

17 · Troubleshooting

Common beginner mistakes

01

Confusing overloading and overriding

Overloading changes parameters; overriding replaces inherited behavior.

02

Using different parameters while overriding

A changed parameter list creates an overload instead of an override. Add @Override so the compiler can warn you.

03

Calling a child-only method from a parent reference

Animal pet can only directly access members declared by Animal, even if the object is a Dog.

04

Unsafe downcasting

Check the actual object with instanceof before converting to a child type.

05

Trying to override a static method

Static methods belong to the class and are hidden, not dynamically overridden.

06

Making access more restrictive

A public parent method cannot be overridden as protected or private.

07

Depending on exact classes everywhere

Use a parent or interface type when only common behavior is needed.

20 · Check your understanding

Quick assessment

Answer each question before opening its answer.

1 What is polymorphism?

Answer: It is the ability to use different objects through a common type while each object provides its own behavior.

2 What is method overriding?

Answer: It is when a child class supplies its own implementation of an inherited method with the same signature.

3 Why does Animal pet = new Dog(); work?

Answer: A Dog is a subtype of Animal, so a parent reference can point to a child object.

4 Which type controls which members can be called?

Answer: The reference type controls which members are visible to the compiler.

5 Which type determines the overridden method that runs?

Answer: The actual object type determines the implementation selected at runtime.

6 What is the main difference between overloading and overriding?

Answer: Overloading changes the parameter list and is resolved at compile time; overriding replaces inherited behavior and is dispatched at runtime.

7 Why is @Override recommended?

Answer: It asks the compiler to confirm that the method correctly overrides an inherited method.

8 What should you check before downcasting?

Answer: Check the object's actual type, normally using instanceof.

9 Can an interface be used as a reference type?

Answer: Yes. Its reference can point to an object of any class that implements the interface.

10 Give one benefit of polymorphism.

Answer: Possible answers include reusable code, easier extension, less duplication, and looser coupling.

11 In Animal pet = new Dog();, what is the reference type?

Answer: Animal is the reference type.

12 In the same declaration, what is the actual object type?

Answer: Dog is the actual object type.

13 Are fields selected using dynamic method dispatch?

Answer: No. Field access is based on the reference type; dynamic dispatch applies to overridden instance methods.

14 Can constructors be overridden?

Answer: No. Constructors are not inherited.

15 How can you test that a design is easy to extend?

Answer: Add a new subtype. Existing code that works with the parent or interface should accept it without needing a new conditional branch.
