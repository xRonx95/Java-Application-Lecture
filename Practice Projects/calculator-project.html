Topic 03

Concept foundation: how a JFrame calculator works

A calculator is an event-driven program. It remains idle until the user clicks a button. Each click produces an event, and the assigned event handler decides how the program should respond.

User clicks a button1 An event is generated2 The handler updates data3 The display shows the result
JF

JFrame

The main application window that contains the calculator interface.

TF

JTextField

The display area used to show entered numbers, operations, and results.

BT

JButton

A clickable control used for digits, operators, commands, and the equals action.

EV

ActionEvent

An object that represents the user clicking a calculator button.

MD

Method

A reusable block of instructions such as appendDigit() or calculateResult().

ST

Program state

Stored information such as the first number, selected operator, and whether a new number should begin.

Teacher explanation: The calculator interface is the visible layer. The variables and methods form the logic layer. Events connect these two layers.

Topic 04

Analyze the project before opening NetBeans

Professional development begins with clear requirements. The class should first identify what the calculator must accept, process, and display.

Input

What the user provides

  • Digits from 0 to 9
  • A decimal point
  • An arithmetic operator
  • A command such as equals or clear
Process

What the program does

  • Stores the first number
  • Stores the chosen operator
  • Reads the second number
  • Performs the selected operation
Output

What the user receives

  • The entered number
  • The calculated result
  • A clear error message
  • A reset display after clearing

Functional requirements

FR-01

The system shall accept whole numbers and decimal numbers.

FR-02

The system shall perform addition, subtraction, multiplication, and division.

FR-03

The system shall display the current entry and the computed result.

FR-04

The system shall clear stored values when the Clear button is selected.

FR-05

The system shall reject a second decimal point in the same number.

FR-06

The system shall report division by zero without closing the window.

Topic 05

Plan the calculator interface

The interface should follow a predictable visual hierarchy: the display comes first, utility commands come next, digits occupy the central area, and arithmetic operators remain visually distinct.

Clarity

Use a large display, high contrast, and labels that students can interpret immediately.

Consistency

Apply equal button sizes, uniform spacing, and a consistent font throughout the keypad.

Feedback

Every button click should produce a visible change or an understandable message.

Error prevention

Block invalid input where possible instead of waiting for the calculation to fail.

Topic 07

Understand the calculator algorithm

The algorithm must preserve the first number and operator while the user enters the second number. The equals button then completes the operation.

  1. 1

    Accept the first number

    Append each digit to the display. Permit only one decimal point.

  2. 2

    Select an operator

    Convert the display text into a number, store it in firstNumber, and remember the selected operator.

  3. 3

    Accept the second number

    Set startNewNumber so the next digit replaces the previous display.

  4. 4

    Calculate the result

    Read the second number, use a switch statement, and store the computed value.

  5. 5

    Display and continue

    Show the result and prepare the calculator for another number or a chained operation.

Calculation decisionLecture excerpt
double secondNumber = Double.parseDouble(displayField.getText());
double result;

switch (operator) {
    case "+" -> result = firstNumber + secondNumber;
    case "-" -> result = firstNumber - secondNumber;
    case "*" -> result = firstNumber * secondNumber;
    case "/" -> {
        if (secondNumber == 0) {
            showError("Division by zero is not allowed.");
            return;
        }
        result = firstNumber / secondNumber;
    }
    default -> {
        showError("Please select an operator.");
        return;
    }
}

displayField.setText(formatResult(result));

Topic 08

Connect buttons to event handlers

Each category of button has a different responsibility. Number buttons build input, operator buttons save state, and command buttons change or evaluate that state.

Digits

Build a number

Append the selected digit to the display or begin a new entry.

Decimal

Control number format

Add a decimal point only when the current entry does not already contain one.

Operators

Store the first operand

Remember the displayed number and the chosen operation.

Equals

Execute the operation

Read the second operand, calculate, and present the result.

Clear

Reset program state

Restore the display, first number, operator, and input status.

Backspace

Correct input

Remove the final character while maintaining a valid display.

Reusable digit methodLecture excerpt
private void appendDigit(String digit) {
    if (startNewNumber || displayField.getText().equals("0")) {
        displayField.setText(digit);
        startNewNumber = false;
    } else {
        displayField.setText(displayField.getText() + digit);
    }
}
Operator methodLecture excerpt
private void chooseOperator(String selectedOperator) {
    firstNumber = Double.parseDouble(displayField.getText());
    operator = selectedOperator;
    startNewNumber = true;
}

Topic 10

Apply input validation and safe error handling

A professional program does not assume that every action is valid. It prevents predictable errors and communicates clearly when an operation cannot be completed.

01

Multiple decimal points

Add a decimal only when the current display does not already contain ..

02

Division by zero

Stop the calculation and display a warning when the second operand is zero.

03

Missing operator

Do not evaluate two numbers until the user has selected a valid operation.

04

Invalid numeric text

Use try-catch when converting display text if manual input is allowed.

05

Long results

Format unnecessary trailing zeros and consider limiting excessive decimal places.

06

Recoverable state

After an error, keep the window open and allow the learner to clear or correct the entry.

Decimal-point validationLecture excerpt
private void appendDecimalPoint() {
    if (startNewNumber) {
        displayField.setText("0.");
        startNewNumber = false;
    } else if (!displayField.getText().contains(".")) {
        displayField.setText(displayField.getText() + ".");
    }
}
Clear calculator stateLecture excerpt
private void clearCalculator() {
    firstNumber = 0.0;
    operator = "";
    startNewNumber = true;
    displayField.setText("0");
}

Topic 12

Common errors and professional corrections

The button does not respond

Confirm that the correct actionPerformed event is connected and that the handler calls the intended method.

Numbers join incorrectly after an operator

Set startNewNumber to true after storing the operator so the next digit replaces the previous display.

NetBeans reports “cannot find symbol”

Check spelling, capitalization, scope, and whether the component or variable was renamed consistently.

The program shows NumberFormatException

The display contains text that cannot be converted to a number. Validate the display before calling Double.parseDouble().

The interface looks uneven

Use a layout manager and consistent preferred sizes. Avoid placing every component with fixed coordinates.

The result contains an unnecessary .0

Use a formatting method that displays whole-number results without a decimal portion.

The JFrame opens in an unexpected location

Call setLocationRelativeTo(null) after pack() so the window appears centered.

Generated code cannot be edited

Return to Design view for guarded components. Place custom methods outside initComponents().

Topic 13

Teacher discussion guide

Use these prompts to move beyond copying code and develop students’ understanding of program design.

Question 1

Why is state necessary?

Guide students to explain why the first number and operator must remain available while the second number is entered.

Question 2

Why use methods?

Compare ten repeated digit handlers with one reusable appendDigit() method.

Question 3

Where should validation occur?

Discuss preventing duplicate decimal points during entry versus detecting invalid input during calculation.

Question 4

What makes an interface usable?

Invite students to identify readable text, predictable placement, feedback, contrast, and adequate button size.

Question 5

What does testing prove?

Explain why boundary and error cases are as important as ordinary calculations.

Question 6

How can the project improve?

Consider keyboard input, calculation history, percentages, memory buttons, and theme options as extensions.

Topic 16

Lesson summary

A Swing calculator is a compact project that combines interface design, event-driven programming, program state, methods, selection structures, numeric conversion, validation, and testing. The principal learning outcome is not the calculator alone—it is the learner’s ability to connect a visible user action to organized Java logic.
