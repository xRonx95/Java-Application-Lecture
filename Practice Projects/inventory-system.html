Inventory Management System Using JFrame Form

A structured, step-by-step lecture on designing and building a desktop-based Inventory Management System using Java Swing components inside a JFrame Form. This module walks through system planning, interface design, event handling, and database connectivity.

Subject: Object-Oriented Programming Tool: NetBeans IDE (GUI Builder) Language: Java (Swing) Duration: 3–4 class sessions

Learning Objectives

At the end of this module, students should be able to:

  • Explain the purpose and structure of a JFrame Form in Java Swing.
  • Identify and apply the appropriate Swing components for an inventory system.
  • Design a functional and organized graphical user interface (GUI) layout.
  • Implement event-handling logic for adding, updating, deleting, and searching records.
  • Connect a JFrame Form to a database using JDBC for data persistence.
  • Apply basic input validation and debugging techniques in a GUI application.
Lesson 01

Introduction to Java Swing and JFrame

Java Swing is a part of the Java Foundation Classes (JFC) used to build graphical user interfaces (GUIs) for desktop applications. It provides a rich set of components — buttons, text fields, tables, labels, and more — that allow a program to be operated visually instead of through the command line.

A JFrame is the main container, or "window," of a Swing application. Every visible component that the user interacts with — text fields, buttons, tables — is placed inside this window.

Common Swing Components Used in This Project

ComponentClass NamePurpose in the Inventory System
LabelJLabelDisplays field names such as "Product ID," "Quantity."
Text FieldJTextFieldAccepts user input such as product name and price.
ButtonJButtonTriggers actions — Add, Update, Delete, Clear, Search.
TableJTableDisplays the list of inventory records in rows and columns.
Combo BoxJComboBoxLets the user select a product category from a fixed list.
Scroll PaneJScrollPaneWraps the table so long lists of records can be scrolled.
Discussion Point Ask the class: why is a graphical interface generally more user-friendly for an inventory clerk than a console-based (text-only) program? Use this to transition into system planning.
Lesson 02

Planning the Inventory System

Before opening the IDE, the class should plan what the system needs to store and what actions it must perform. Good planning prevents redesigning the form later.

Data Fields to Capture

FieldData TypeDescription
Product IDString / IntegerUnique identifier for each product.
Product NameStringName of the item in stock.
CategoryStringClassification, selected from a combo box.
QuantityIntegerNumber of units currently on hand.
Unit PriceDoublePrice per unit, used to compute total value.

Core System Functions (CRUD)

The system will support the four fundamental data operations, commonly abbreviated as CRUD:

  • Create — add a new product record.
  • Read — display and search existing records in the table.
  • Update — edit the details of a selected record.
  • Delete — remove a record from the system.
Teaching Tip Have students sketch the form layout on paper first, labeling every field and button, before they touch the GUI builder. This reinforces planning as a separate step from implementation.
Lesson 03

Setting Up the Project

This lesson introduces the development environment used to build and run the JFrame Form.

  1. Install the Java Development Kit (JDK)

    Confirm that a current JDK is installed. This provides the compiler and runtime needed to build the application.

  2. Open the NetBeans IDE

    NetBeans includes a visual GUI Builder (Matisse) that allows Swing components to be arranged by dragging and dropping, rather than positioning them manually in code.

  3. Create a New Java Application

    File → New Project → Java with Ant / Java Application. Name the project, for example, InventorySystem.

  4. Add a New JFrame Form

    Right-click the project's source package → New → JFrame Form. Name it InventoryForm. This creates the blank window shown in Figure 1.

Lesson 04

Designing the JFrame Form

With the blank form ready, components are added one at a time. Explain each step aloud while pointing to the corresponding part of Figure 3.

  1. Step 1 — Add Labels

    Drag a JLabel for each data field: Product ID, Product Name, Category, Quantity, and Price. Labels describe what each input field is for.

  2. Step 2 — Add Text Fields

    Place a JTextField beside each label so the user can type in values.

  3. Step 3 — Add a Combo Box for Category

    Insert a JComboBox next to the Category label and populate it with fixed category choices, such as Electronics, Office Supplies, and Groceries.

  4. Step 4 — Add Action Buttons

    Place four buttons: Add, Update, Delete, and Clear. Each will later be linked to its own event-handling method.

  5. Step 5 — Add a Table Inside a Scroll Pane

    Drag a JTable onto the form. NetBeans automatically wraps it inside a JScrollPane, which allows the list to scroll when there are many records.

Lesson 06

Displaying Records in a JTable

A JTable does not store data by itself; it displays data supplied by a table model. The simplest option is DefaultTableModel, which can be filled with column headers and rows programmatically.

InventoryForm.java — Initializing the table model 
DefaultTableModel model = new DefaultTableModel();
model.setColumnIdentifiers(new String[] {
    "Product ID", "Product Name", "Category", "Quantity", "Price"
});
tblInventory.setModel(model);

// Adding a sample row to the table
model.addRow(new Object[] {
    "1001", "Wireless Mouse", "Electronics", 35, 450.00
});
Teaching Tip Demonstrate this in class by running the program and adding two or three sample rows live, so students can see the connection between the code and what appears on the table.
Lesson 07

Writing the Event-Handling Code

Each button needs an ActionListener so the program responds when it is clicked. In NetBeans, double-clicking a button in Design view automatically generates an empty event method — the student then fills in the logic.

Add Button

btnAddActionPerformed 
private void btnAddActionPerformed(java.awt.event.ActionEvent evt) {
    String id       = txtProductID.getText();
    String name     = txtProductName.getText();
    String category = cmbCategory.getSelectedItem().toString();
    String qty      = txtQuantity.getText();
    String price    = txtPrice.getText();

    DefaultTableModel model = (DefaultTableModel) tblInventory.getModel();
    model.addRow(new Object[] { id, name, category, qty, price });

    clearFields();
}

Delete Button

btnDeleteActionPerformed 
private void btnDeleteActionPerformed(java.awt.event.ActionEvent evt) {
    int selectedRow = tblInventory.getSelectedRow();

    if (selectedRow >= 0) {
        DefaultTableModel model = (DefaultTableModel) tblInventory.getModel();
        model.removeRow(selectedRow);
    } else {
        JOptionPane.showMessageDialog(this, "Please select a record to delete.");
    }
}

Clear Button

btnClearActionPerformed 
private void btnClearActionPerformed(java.awt.event.ActionEvent evt) {
    clearFields();
}

private void clearFields() {
    txtProductID.setText("");
    txtProductName.setText("");
    txtQuantity.setText("");
    txtPrice.setText("");
    cmbCategory.setSelectedIndex(0);
}
Discussion Point Walk through the flow of control: a user click → triggers the ActionEvent → calls the listener method → updates the table model → the JTable repaints automatically.
Lesson 08

Connecting to the Database (JDBC)

For records to persist after the program closes, the form must be connected to a database such as MySQL, using JDBC (Java Database Connectivity).

Step 1 — Establish the Connection

DBConnection.java 
public class DBConnection {
    public static Connection getConnection() {
        Connection con = null;
        try {
            String url = "jdbc:mysql://localhost:3306/inventory_db";
            con = DriverManager.getConnection(url, "root", "");
        } catch (SQLException e) {
            System.out.println("Connection failed: " + e.getMessage());
        }
        return con;
    }
}

Step 2 — Insert a New Record

Add operation using PreparedStatement 
String sql = "INSERT INTO products (id, name, category, qty, price) VALUES (?,?,?,?,?)";
PreparedStatement ps = con.prepareStatement(sql);
ps.setString(1, txtProductID.getText());
ps.setString(2, txtProductName.getText());
ps.setString(3, cmbCategory.getSelectedItem().toString());
ps.setInt(4, Integer.parseInt(txtQuantity.getText()));
ps.setDouble(5, Double.parseDouble(txtPrice.getText()));
ps.executeUpdate();

Step 3 — Retrieve and Display Records

Read operation, populating the table on form load 
String sql = "SELECT * FROM products";
ResultSet rs = con.createStatement().executeQuery(sql);
DefaultTableModel model = (DefaultTableModel) tblInventory.getModel();

while (rs.next()) {
    model.addRow(new Object[] {
        rs.getString("id"), rs.getString("name"),
        rs.getString("category"), rs.getInt("qty"), rs.getDouble("price")
    });
}
Common Mistake Remind students to always close the Connection, Statement, and ResultSet objects (or use try-with-resources) to avoid leaving database connections open.
Lesson 09

Input Validation and Debugging

A reliable inventory system must guard against blank fields and invalid numeric entries before a record is saved.

Basic validation before saving a record 
private boolean isInputValid() {
    if (txtProductName.getText().trim().isEmpty()) {
        JOptionPane.showMessageDialog(this, "Product name cannot be empty.");
        return false;
    }
    try {
        Integer.parseInt(txtQuantity.getText());
        Double.parseDouble(txtPrice.getText());
    } catch (NumberFormatException e) {
        JOptionPane.showMessageDialog(this, "Quantity and price must be numeric.");
        return false;
    }
    return true;
}

Debugging Checklist for Students

  • Confirm every component name in the code matches the name in the Properties panel.
  • Check that the database driver (JDBC connector) is added to the project libraries.
  • Use System.out.println() statements to trace values before an operation runs.
  • Wrap database calls in try–catch blocks and read the exception message carefully.
Lesson 10

Summary and Key Takeaways

  • A JFrame serves as the main window that hosts all Swing components of the application.
  • System planning — defining data fields and required operations — should precede interface design.
  • Labels, text fields, combo boxes, buttons, and a table together form the complete data-entry interface.
  • Clear, descriptive component names make event-handling code easier to write and review.
  • A DefaultTableModel connects the visual JTable to the underlying data.
  • ActionListener methods implement the Add, Update, Delete, Clear, and Search operations.
  • JDBC allows the form to store and retrieve data permanently from a database.
  • Input validation protects the system from blank or invalid data before it is saved.
