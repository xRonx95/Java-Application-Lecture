Practice Project Module 02

Designing a Login System Using JFrame

A structured lecture on Java Swing interface design, event handling, input validation, and responsible authentication concepts.

Level: Intermediate Format: Lecture and guided analysis Estimated time: 90–120 minutes
Begin the lesson

Module overview

What students will learn

The purpose of this module is to explain how a graphical login form is planned and assembled. It focuses on reasoning, structure, and good programming habits—not on distributing a finished Java application.

01

Interface construction

Identify how JFrame, JPanel, JLabel, JTextField, JPasswordField, JCheckBox, and JButton work together.

02

Layout management

Use layout managers to create an organized interface that is easier to maintain than absolute positioning.

03

Event-driven behavior

Explain how an ActionListener responds when a user selects a button or toggles password visibility.

04

Validation and feedback

Check empty inputs, compare sample credentials, and present clear messages without exposing passwords.

05

Security awareness

Distinguish a classroom demonstration from a production authentication system with a database and password hashing.

06

Testing and reflection

Prepare test cases, interpret results, and suggest responsible improvements to the program design.

Topic 1

Understanding the login process

A login interface collects credentials, validates the input, checks an authentication source, and returns a result. Each responsibility should be explained separately so that the program remains understandable.

!

Professional distinction

The sample credentials used in a classroom exercise demonstrate control flow only. A real system must store salted password hashes, use a secure database connection, apply access controls, and protect sensitive data.

Guided lesson

Step-by-step lecture sequence

Present each step in order. Ask students to predict the next component or behavior before revealing the explanation.

Step 1

Plan the interface before writing code

Identify the information, actions, messages, and visual order required by the login form.

Lecture points

  • Keep the form focused on one task: authenticating a user.
  • Place labels immediately above or beside their related inputs.
  • Make the primary action visually clear and keep feedback near the form.
  • Choose meaningful component names before implementation.
Step 2

Import the required Swing and AWT classes

Imports make the graphical components, layouts, colors, fonts, and events available to the class.

import javax.swing.*;
import java.awt.*;
import java.awt.event.ActionEvent;
import java.util.Arrays;

Explain it professionally

javax.swing supplies interface components. java.awt supplies layouts, dimensions, colors, and fonts. ActionEvent represents a user action such as pressing a button.

For introductory lessons, wildcard imports reduce visual clutter. In production code, explicit imports can improve clarity.

Step 3

Create the class and declare fields

Component fields allow multiple methods to read or update the same interface controls.

public class LoginSystemLesson extends JFrame {
    private final JTextField usernameField = new JTextField();
    private final JPasswordField passwordField = new JPasswordField();
    private final JCheckBox showPasswordCheckBox =
        new JCheckBox("Show password");
    private final JLabel messageLabel = new JLabel(" ");
}

private protects the fields from unrelated classes.

final means the field reference will not be assigned to a different component.

extends JFrame makes the lesson class itself a window.

Step 4

Configure the window safely

The constructor defines the title, closing behavior, size, position, and initial interface.

public LoginSystemLesson() {
    setTitle("Account Login");
    setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
    setContentPane(createMainPanel());
    pack();
    setMinimumSize(new Dimension(520, 460));
    setLocationRelativeTo(null);
}
setTitle()Names the window.
setDefaultCloseOperation()Defines what happens when it closes.
setMinimumSize()Prevents an unusably small layout.
setLocationRelativeTo(null)Centers the window.
setContentPane()Installs the main interface panel.
pack()Sizes the window from preferred component sizes.
Step 5

Organize controls with layout managers

Layout managers calculate positions and respond better to font, operating-system, and window-size differences.

Recommended combination

  1. Use BorderLayout for the main page regions.
  2. Use GridBagLayout for aligned labels and input fields.
  3. Use BoxLayout for vertically stacked groups.
  4. Add empty borders to create consistent internal spacing.
Avoid as the default approach:

setLayout(null) and fixed pixel coordinates often break when fonts, screen scaling, or text length changes.

Step 6

Read the password with care

JPasswordField returns a character array so the value can be cleared after it is used.

char[] passwordCharacters = passwordField.getPassword();

try {
    String password = new String(passwordCharacters);
    // Use only for this classroom comparison.
} finally {
    Arrays.fill(passwordCharacters, '\0');
}
i

Instructor emphasis

Converting a password to String leaves an immutable value in memory until garbage collection. This sample is useful for explaining a comparison, but production authentication should avoid unnecessary password copies and should verify a secure hash.

Step 7

Respond to user actions

Listeners connect visible controls to program behavior.

char defaultEcho = passwordField.getEchoChar();

loginButton.addActionListener(
    this::handleLogin
);

showPasswordCheckBox.addActionListener(event -> {
    char echo = showPasswordCheckBox.isSelected()
        ? (char) 0
        : defaultEcho;
    passwordField.setEchoChar(echo);
});
Step 8

Validate inputs before authentication

Validation checks whether the input is usable; authentication checks whether the credentials are correct.

private void handleLogin(ActionEvent event) {
    String username = usernameField.getText().trim();
    char[] password = passwordField.getPassword();

    if (username.isEmpty() || password.length == 0) {
        showMessage("Enter both username and password.", false);
        Arrays.fill(password, '\0');
        return;
    }

    boolean isValid = username.equals("student")
        && Arrays.equals(password, "LearnJava123".toCharArray());

    showMessage(isValid ? "Login successful."
                        : "Invalid username or password.", isValid);
    Arrays.fill(password, '\0');
}

Validation

“Are the required fields present and in an acceptable format?”

  • Empty username
  • Empty password
  • Unexpected input length

Authentication

“Do the supplied credentials belong to a permitted account?”

  • Account lookup
  • Password-hash verification
  • Access decision
Step 9

Start Swing on the Event Dispatch Thread

Swing components should be created and updated on the thread responsible for interface events.

public static void main(String[] args) {
    SwingUtilities.invokeLater(() -> {
        LoginSystemLesson window = new LoginSystemLesson();
        window.setVisible(true);
    });
}

Key explanation: invokeLater schedules interface creation on Swing’s Event Dispatch Thread. Long-running database or network work should not run directly on this thread because it would freeze the interface.

Extended topics

Professional concepts beyond the basic form

Use these topics to deepen the discussion after students understand the component and event flow.

01

Separation of concerns

Keep interface construction, validation, and authentication logic in separate methods or classes.

02

Password hashing

Store a salted hash—not a plaintext password—and verify it with an established password-hashing library.

03

Database access

Use prepared statements, least-privilege database accounts, and a dedicated data-access layer.

04

Accessible feedback

Use descriptive labels, keyboard focus, readable contrast, and feedback that is not communicated by color alone.

05

Failure handling

Show a neutral message to the user, record technical details safely, and never expose stack traces or database errors.

06

Rate limiting

Slow repeated failed attempts and monitor suspicious activity without permanently locking legitimate users out.

07

Session state

After authentication, maintain only the identity and permissions needed by the application.

08

Maintainable styling

Centralize colors, fonts, dimensions, and component factories to keep a consistent visual system.

Assessment and practice

Check understanding

Use the questions for oral recitation, written reflection, or a short formative assessment.

Question 1

Why is JPasswordField preferred over JTextField for passwords?

Guide: It masks visible characters and provides the password as a character array.

Question 2

What is the difference between validation and authentication?

Guide: Validation checks input quality; authentication verifies identity.

Question 3

Why are layout managers preferred over fixed coordinates?

Guide: They adapt to fonts, scaling, content, and window size.

Question 4

Why should a database password never be stored as plaintext?

Guide: A breach would immediately expose every stored password.

Question 5

What is the role of an ActionListener?

Guide: It receives a user action event and invokes the required behavior.

Question 6

What work should not run directly on Swing’s event thread?

Guide: Long database, file, or network operations that can freeze the interface.

Student practice challenge

Improve the design on paper or in pseudocode

Ask students to propose changes without requiring a finished Java application.

  1. Add a maximum-attempt policy with a temporary delay.
  2. Design a separate authentication service interface.
  3. Write three additional boundary test cases.
  4. Explain how database password hashing would replace the classroom comparison.

Quick reference

Key terms

Authentication
Verifying that a claimed identity is genuine.
Authorization
Determining what an authenticated user may access.
Event
An occurrence, such as a click, that the program can respond to.
Layout manager
An object that calculates component size and position.
Password hash
A one-way derived value used to verify a password without storing it directly.
Validation
Checking whether input is complete and follows expected rules.

Lesson conclusion

A professional login form begins with clear responsibilities.

Students should leave this lesson able to explain how Swing components, layout managers, listeners, validation, authentication, security, and testing contribute to the complete login process.
